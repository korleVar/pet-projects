# Описание контролей


> В Ex.06 описываем **контроли (валидации)** на экранах, где есть **ввод/корректировка**.
> Ниже перечислены экраны из Ex.04, которые содержат операции ввода/изменения данных.

Легенда:
- Роли: **C** (Client), **M** (Manager), **B** (Master)
- Результат при негативном контроле: операция **не выполняется**, поле подсвечивается, показывается сообщение
- Неопределённые значения на UI: `—`

Общие служебные поля логирования:
- `timestamp`, `user_id`, `user_role`, `screen_id`, `operation`, `entity_type`, `entity_id` (если есть), `correlation_id`

## 2.1 C-SCR-07 — Регистрация клиента (Client)

**Роль:** C  
**Операция:** `create_client`  
**Пагинация:** нет

| Поле    | Мнемо    | Описание контроля                             | Ошибка при негативе                                    | Результат при негативе   | Результат при позитиве            | Логировать негатив? |
|---------|----------|-----------------------------------------------|--------------------------------------------------------|--------------------------|-----------------------------------|---------------------|
| Телефон | phone    | Проверка формата по маске + уникальность      | `Некорректный телефон` / `Телефон уже зарегистрирован` | Регистрация не создаётся | Телефон принят                    | Да                  |
| Имя     | name     | Не пустое, ≥2 символа                         | `Имя обязательно`                                      | Регистрация не создаётся | Имя принято                       | Да                  |
| Пароль  | password | Минимальная сложность (длина/классы символов) | `Пароль слишком слабый`                                | Регистрация не создаётся | Пароль принят, показываем уровень | Да                  |

**Логирование негативных контролей**

| Операции      | Атрибуты                                    | Служебные поля                         |
|---------------|---------------------------------------------|----------------------------------------|
| validate_fail | screen_id, field, reason, input_hash(phone) | timestamp, user_role=C, correlation_id |

> Примечание: телефон/пароль не логировать “как есть”; телефон — можно в виде маски/хеша.

# 4. Параметры логирования негативных контролей 

| Тип события    | Когда пишем                                      | Атрибуты (минимум)                                                |
|---|---|---|
| validate_fail  | любая ошибка поля                                | screen_id, field, reason, entity_type, entity_id(optional)        |
| operation_fail | ошибка операции (конфликт слота/переход статуса) | operation, reason, ключевые параметры (slot_datetime, booking_id) |
| auth_fail      | неверный логин/пароль                            | login_hash, attempts_count                                        |

Служебные поля: `timestamp, user_id, user_role, correlation_id`.
